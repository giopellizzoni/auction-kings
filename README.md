# AuctionKings

A real-time auction platform built with ASP.NET Core 10, featuring WebSocket-based bidding, Domain-Driven Design, and comprehensive testing.

## Tech Stack

- **Framework**: ASP.NET Core 10.0
- **Language**: C# with nullable reference types
- **Architecture**: Clean Architecture + DDD
- **Real-time**: SignalR (WebSockets) + Redis backplane; the background worker reaches the hubs through a Redis Stream relay
- **Messaging**: Transactional Outbox publishing to AWS SQS
- **Database**: PostgreSQL 16
- **Cache**: Redis 7
- **Background workers**: .NET Worker Service
- **Testing**: xUnit + Testcontainers + NBomber

## Prerequisites

- [.NET 10.0 SDK](https://dotnet.microsoft.com/download/dotnet/10.0)
- [Docker Desktop](https://www.docker.com/products/docker-desktop)
- Optional: EF Core CLI (`dotnet tool install --global dotnet-ef`) to add or apply migrations by hand
- A POSIX shell with `openssl` for `scripts/setup-local-env.sh` (Git Bash works on Windows)

## Running the Project

Both options below start from the same first step:

```bash
# Generates docker/secrets/postgres_password.txt, redis_password.txt and grafana_admin_password.txt
# (if missing), and writes .env.local (repo root) + docker/.env.local from them. Idempotent — safe to
# re-run, never overwrites a file that already exists.
./scripts/setup-local-env.sh
```

**Database schema.** In both options the API creates and upgrades the schema itself: on startup it
applies any pending EF Core migrations when `Database:MigrateOnStartup` is `true`, which
`appsettings.Development.json` sets (so `dotnet run` and the Docker stack). Staging enables it
too (`Database__MigrateOnStartup=true` in `infra/terraform/staging/ecs.api.tf`); any other
environment leaves it off unless it sets that variable. To migrate by hand instead, see
[docs/runbook.md §0](docs/runbook.md#0-local-setup-from-a-clean-checkout).

### Option A — Full Docker Stack

Starts API, background workers, PostgreSQL, Redis, LocalStack, Prometheus, and Grafana in one command.

The `api`/`worker` containers (unlike the infra-only containers) read `POSTGRES_PASSWORD`, `REDIS_PASSWORD`, and `JWT_SECRET` as plain environment variables, from `docker/.env.local` — `docker compose` does **not** auto-load it, so you must pass it explicitly with `--env-file`:

```bash
cd docker
docker compose --env-file .env.local up -d
```

**MediatR license (optional).** MediatR 13+ asks for a license key. The free Community edition needs a key you register yourself; set it as `MediatR__License` in the git-ignored root `.env.local` for `dotnet run`, or as `MEDIATR_LICENSE` in `docker/.env.local` for the full Docker stack. Without one MediatR may log a license warning. Never commit the key.

If you forget `--env-file .env.local`, those three variables interpolate to empty strings — the API will refuse to start (`'Jwt:Secret' is not configured`) and fail to authenticate with Redis (`NOAUTH`).

Services available after startup (~15 seconds):

| Service    | URL                                     |
| ---------- | --------------------------------------- |
| API        | <http://localhost:5081>                 |
| API reference (Scalar) | <http://localhost:5081/scalar> — Development only; OpenAPI JSON at `/openapi/v1.json`. There is no Swagger UI. |
| Grafana    | <http://localhost:3000> (user `admin`; password in `docker/secrets/grafana_admin_password.txt`, generated by `./scripts/setup-local-env.sh`) |
| Prometheus | <http://localhost:9090>                 |
| LocalStack | <http://localhost:4566>                 |

### Option B — Local Development (dotnet run, recommended for iterating)

```bash
# 1. Start infrastructure (PostgreSQL, Redis, LocalStack, Prometheus, Grafana)
cd docker && docker compose -f docker-compose.infra.yml up -d && cd ..

# 2. Restore and build
dotnet restore && dotnet build

# 3. Run the API (http://localhost:5081, API reference at /scalar) — applies pending migrations on startup
dotnet run --project src/services/AuctionKings.API/AuctionKings.API.csproj

# 4. Run background workers in a separate terminal (needed for outbox dispatch and auction auto-close)
dotnet run --project src/workers/AuctionKings.BackgroundWorkers/AuctionKings.BackgroundWorkers.csproj
```

No JWT signing key is committed to the repo. `setup-local-env.sh` generates a random
`Jwt__Secret` (256 bits) into the git-ignored `.env.local`, and adds one to an existing
`.env.local` that lacks it. If it is missing, empty, shorter than 32 bytes, or the old
committed placeholder, the API refuses to start with a message that points back to the script.

## Authenticating with Cognito

Amazon Cognito is the identity provider: accounts, sign-up, sign-in and passwords live in a Cognito user
pool, and the API only validates the RS256 **access tokens** Cognito issues. Cognito groups are the roles:

| Group    | Can                                                      |
| -------- | -------------------------------------------------------- |
| `Bidder` | create auctions, place bids                              |
| `Admin`  | close auctions, read any user's bid history              |
| _(none)_ | signed in: read public data and their own bid history    |

The user id the API sees (`sellerId`, `bidderId`, `/users/{id}`) is the Cognito `sub`.

Locally, Cognito is emulated by **Moto** (port 5555), started by the infra compose file. Its
`moto-init` container seeds a pool, an app client, the two groups and three accounts, with fixed ids that
`appsettings.Development.json` already points to. Nothing to configure.

### Local walkthrough

Requires the AWS CLI v2 and `jq` (Git Bash on Windows). Start infra and the API as in
[Option B](#option-b--local-development-dotnet-run-recommended-for-iterating) (or Option A), then:

```bash
# Moto accepts any credentials; these never leave your machine.
export AWS_ACCESS_KEY_ID=testing AWS_SECRET_ACCESS_KEY=testing AWS_DEFAULT_REGION=us-east-1 AWS_PAGER=""
COGNITO="aws cognito-idp --endpoint-url http://localhost:5555"
POOL=us-east-1_d85380f7cde7bc8c1b0ca2ed3ee5ddc1affc77945b39d   # Cognito:UserPoolId
CLIENT=123b1f3863b67d1a3e89103c68                              # Cognito:ClientIds[0]
API=http://localhost:5081
```

**1. Create an account** (or skip to step 2 with a seeded one: `seller@test.com`, `buyer@test.com`
(`Bidder`) and `admin@test.com` (`Admin`), password `Test1234!`):

```bash
$COGNITO sign-up --client-id $CLIENT --username ann@example.com --password 'Correct-horse-42' \
  --user-attributes Name=email,Value=ann@example.com Name=name,Value=Ann

# Real Cognito emails a code (confirm-sign-up --confirmation-code ...); locally, confirm as admin:
$COGNITO admin-confirm-sign-up --user-pool-id $POOL --username ann@example.com

# A new account is in no group. Make it a Bidder:
$COGNITO admin-add-user-to-group --user-pool-id $POOL --username ann@example.com --group-name Bidder
```

**2. Sign in** and keep the access token (not the ID token: the API rejects ID tokens):

```bash
signin() {  # signin <email> <password> → prints the access token
  $COGNITO initiate-auth --client-id $CLIENT --auth-flow USER_PASSWORD_AUTH \
    --auth-parameters "USERNAME=$1,PASSWORD=$2" --query AuthenticationResult.AccessToken --output text
}
SELLER_TOKEN=$(signin ann@example.com 'Correct-horse-42')
BUYER_TOKEN=$(signin buyer@test.com 'Test1234!')
```

**3. Create an auction** as Ann. The response body is the new auction id:

```bash
AUCTION_ID=$(curl -s -X POST $API/api/v1/auctions \
  -H "Authorization: Bearer $SELLER_TOKEN" -H "Content-Type: application/json" \
  -d '{"title":"Vintage camera","description":"Works perfectly","startingPrice":100,"currency":"USD","durationInHours":24}' \
  | jq -r .)
echo $AUCTION_ID
```

**4. Bid** as the buyer (a seller cannot bid on their own auction). `X-Request-Id` is a required
idempotency key: resending the same id does not place a second bid.

```bash
curl -s -X POST $API/api/v1/auctions/$AUCTION_ID/bids \
  -H "Authorization: Bearer $BUYER_TOKEN" -H "Content-Type: application/json" \
  -H "X-Request-Id: $(cat /proc/sys/kernel/random/uuid 2>/dev/null || uuidgen)" \
  -d '{"amount":120,"currency":"USD"}'
```

**5. Read it back:**

```bash
curl -s $API/api/v1/auctions/$AUCTION_ID | jq .     # public, no token

BUYER_ID=$($COGNITO get-user --access-token "$BUYER_TOKEN" \
  --query "UserAttributes[?Name=='sub'].Value | [0]" --output text)
curl -s $API/api/v1/users/$BUYER_ID/bids -H "Authorization: Bearer $BUYER_TOKEN" | jq .
```

**If something answers 401 or 403:**

- `401`: no token, an expired one (sign in again), an ID token instead of the access token, or a token
  from another pool or app client. Moto keeps everything in memory, so after it restarts, re-seed it with
  `cd docker && docker compose -f docker-compose.infra.yml up moto-init` and sign in again.
- `403`: signed in, but not in the group the endpoint needs (`Bidder` to create or bid, `Admin` to close).

The same requests (with a token pasted in) are in
[`AuctionKings.API.http`](src/services/AuctionKings.API/AuctionKings.API.http), and the Scalar UI at
<http://localhost:5081/scalar> has an Authorize button that takes a bearer token.

### Staging

Terraform creates a real user pool (`infra/terraform/staging/cognito*.tf`), and the API task is configured
with its id. Use the same commands without `--endpoint-url`, with your AWS credentials:

```bash
COGNITO="aws cognito-idp --region us-east-1"
cd infra/terraform/staging
POOL=$(terraform output -raw users_cognito_user_pool_id)
CLIENT=$(terraform output -raw api_cognito_user_pool_client_id)
API=$(terraform output -raw alb_url)
```

The differences from local: `sign-up` emails a verification code, so confirm with
`$COGNITO confirm-sign-up --client-id $CLIENT --username <email> --confirmation-code <code>`. Adding a user
to a group (`admin-add-user-to-group`) needs IAM credentials for the pool. The password policy is
8+ characters with a lowercase letter and a number. A staging teardown deletes the pool and its accounts.

### Without Cognito: dev tokens

In Development (and, key-protected, in staging) `POST /dev/token` still mints a local HS256 token for
any user id and role. It is handy for scripts and tests, and is never a way to sign in real users:

```bash
curl -s -X POST $API/dev/token -H "Content-Type: application/json" \
  -d '{"userId":"00000000-0000-0000-0000-000000000001","role":"Admin"}' | jq -r .token
```

## Configuration

Run the bootstrap script once per checkout — it generates secrets and both `.env.local` files for you:

```bash
./scripts/setup-local-env.sh
```

`.env` (repo root) is committed and documents every variable `dotnet run` reads; `docker/.env`
documents what `docker compose` interpolates. Both `.env.local` files are git-ignored and hold
real generated values. If you prefer to edit them by hand instead of using the script, `.env`
and `docker/.env` are the templates — but the root `.env.local` must contain a `Jwt__Secret` of at
least 32 bytes (for example `openssl rand -hex 32`). `Issuer`/`Audience` come from
`appsettings.Development.json`; leave them out of `.env.local`.

- `dotnet run` loads `.env.local` automatically (via `DotNetEnv` in `Program.cs`) — no extra step needed.
- `docker compose` does **not** auto-load `.env.local` (only `.env`). Pass it explicitly: `docker compose --env-file .env.local up -d`.

### CORS

Browser origins allowed to call the REST API and SignalR hubs are listed in `Cors:AllowedOrigins`
(empty by default, meaning no cross-origin browser access). Entries must be exact origins — `https://host[:port]`,
no path, trailing slash, or wildcard — or the API refuses to start.

```jsonc
// appsettings.{Environment}.json
"Cors": { "AllowedOrigins": ["http://localhost:5173"] }
```

As environment variables: `Cors__AllowedOrigins__0=https://app.example.com`, `Cors__AllowedOrigins__1=...`.
Non-browser clients (the .NET SignalR client, k6 load tests, curl) are not affected. See ADR-004 in `docs/decisions.md`.

### SignalR throttling

The hubs limit abuse through the `HubThrottling` section of `appsettings.json` (defaults shown):

```jsonc
"HubThrottling": {
  "MaxInvocations": 20,          // hub method calls per user per window, across all connections
  "Window": "00:00:10",
  "MaxConnectionsPerUser": 10,   // AuctionHub and NotificationHub share one count
  "MaxGroupsPerConnection": 20,  // auctions one connection may be joined to
  "MaxMessageSizeBytes": 8192
}
```

Every value must be greater than zero or the API refuses to start. Override per environment with
`HubThrottling__MaxInvocations=40` etc. Clients over the call limit get a `HubException`; see ADR-007 in `docs/decisions.md`.

### Background workers

The worker host validates its configuration at startup and refuses to start, naming the key, when
`ConnectionStrings:DefaultConnection` or `ConnectionStrings:Redis` is blank, or when a polling interval,
batch size, retry count or retention (`Outbox`, `AuctionCloseWorker`, `AuctionActivationWorker`,
`CleanupWorker` sections) is not greater than zero.

The worker has no SignalR. Real-time pushes it raises (for example `AuctionClosed`, or the notice sent to a
seller whose auction was cancelled) go to a Redis Stream and the API relays them to the hubs. The relay is
tuned through the `RealtimeRelay` section (defaults shown; every value must be positive):

```jsonc
"RealtimeRelay": {
  "PollInterval": "00:00:00.500",  // wait before polling an empty stream again
  "ErrorDelay": "00:00:02",
  "BatchSize": 50,
  "ClaimIdle": "00:01:00",         // an entry unacknowledged this long is taken over by another replica
  "ClaimEvery": "00:00:30",
  "MaxAge": "00:10:00"             // older entries are dropped
}
```

Delivery is at least once. See ADR-011 in `docs/decisions.md`.
